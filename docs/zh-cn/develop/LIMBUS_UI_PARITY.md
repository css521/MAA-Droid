# 边狱巴士页面移植对照

对照版本：LALC v5.0.0（431b432e22f0b0da08b95d7c478fa213be20b3e8）、AALC V1.5.2-beta.70。以本地上游源码核对字段和执行读取点，用户截图中的 AALC V0.4 仅作界面参考。

## 两个上游的区别

| 内容 | LALC | AALC | Android 的选择 |
|---|---|---|---|
| 页面组织 | 任务、工作日志、队伍、主题卡包 | 一键长草、队伍、主题卡包、小工具、设置 | 边狱游戏标签下的任务、队伍、卡包、日志 |
| 队伍 | 20 槽位；罪人点击顺序；任务选择队伍后轮换 | 队伍体系、商店策略、额外战斗/观测策略 | 采用 LALC 槽位和顺序，不能混用 AALC 的配置键 |
| 镜牢 | 流派、饰品允许/排除、融合/购买/强化、技能替换、星光、路径权重 | 另有售卖策略、弃用体系、观测饰品、更多逐层行为 | 实现 LALC 的选项；未给 AALC 独有策略放无效开关 |
| 执行结构 | JSON 流程和 Python handler | Python 任务与独立配置模型 | Kotlin 移植 LALC handler，加载原 JSON 流程 |
| 更新源 | HSLix/LixAssistantLimbusCompany | KIYI671/AhabAssistantLimbusCompany | 仅下载 LALC 自动化资源；不混用 AALC 图片和模型 |

来源代码：LALC `lalc_frontend/lib/pages/{task_page,team_config_page,theme_pack_page,work_page}.dart`、`managers/config_manager.dart`、`lalc_backend/server.py`；AALC `app/{farming_interface,team_setting_card,theme_pack_setting_interface}.py` 与 `assets/config/config.example.yaml`。

## 当前 Android 页面

入口：后台任务 → 边狱巴士。页面、图鉴、配置转换均在 `engine/limbus`，通过 `EngineUi.workspace` 装配，宿主不引用罪人、队伍或镜牢类型。

游戏预览使用与方舟相同的 16:9 尺寸和横向边距；点预览或放大按钮进入全屏，
在全屏中操作游戏。收起仅释放预览 Surface，不停止自动化。任务停止后仍保留游戏画面和手动输入，
下次启动任一游戏前再释放旧显示会话。非全屏且游戏画面可用时按 Home
可进入系统画中画，遵循宿主“回桌面进入画中画”设置；系统小窗只显示游戏画面。
手动触控使用当前设备会话的独立触点，退出、切页或旋转时释放，不能操作后续新会话。
图鉴上方的大标题已去掉，导入/导出在任务标签行末尾的“更多”菜单。

`core/ui` 提供两款游戏共用的预览外框、紧凑标签、日志面板与行样式、主/次操作按钮。
边狱与方舟首页更新卡片共用显式 `surface` 背景，避免 Material 默认卡片色带来额外的紫灰色。
展开预览时，放大/收起按钮浮在画面右下角，不再占用上方独立一行；收起时保留恢复入口。
任务页底部使用与方舟相同的圆角按钮与间距，运行前显示开始、运行时显示停止；日志保留各自
业务内容，方舟的时间、等级、公招详情和清空/导出操作仍由原页面提供。

| 页面 | 已接入的内容 |
|---|---|
| 任务 | 邮件、经验、纺锤、镜牢、奖励；执行次数、关卡、进入/跳过战斗、队伍选择顺序；E.G.O、每日狂气兑换、结束游戏 |
| 镜牢任务设置 | 难度、保留货币、融合饰品、替换技能与购买饰品、强化、领奖、七类节点权重 |
| 队伍 | 20 槽位、名称、复制配置、12 罪人图片与出战顺序、流派、全体治疗 |
| 星光与开局 | 10 星光及基础/+ /++ 等级、初始饰品选择顺序 |
| 饰品 | 332 张上游图鉴；中文/英文名称搜索；流派筛选、首选流派、单件允许/排除 |
| 技能替换 | 每位罪人独立开关，1→3、2→3、1→2 的优先级 |
| 卡包 | 95 个上游主题卡包图文、搜索、权重及排序 |
| 日志 | 当前会话最近 500 条信息/警告/错误，可复制 |
| 配置 | 自动保存、JSON 复制导出、合并形态的 LALC JSON 导入；旧五开关页面的选中状态、关卡、领奖选项迁移 |

配置格式沿用上游 `taskConfigs`、`teamConfigs`、`themePackWeights`。桌面各自独立的配置文件需要合成该顶层结构后导入；不把桌面 ZIP 配置集当作已支持。手机不提供关闭电脑、Windows 进程路径或 WebSocket 服务器设置；运行结束可保持或结束游戏。

上游页面有 `battle_fail_handle` 字段，但当前 v5.0.0 的 `server.py` 转换函数未传给引擎。Android 没有把它做成可编辑的无效选项。AALC 的额外配置需要单独实现动作后才能加入。

## 配置到执行

`LimbusWorkspaceConfig` → 五个上游配置分节 → `EngineTaskStore` 原样保存 → `appendTask` → 运行时同一配置快照。

- 队伍以所选顺序生成 `team_indexes`、`team_orders` 和镜牢平行数组，保留 1–20 的游戏槽位，不按槽位重排。
- 任务次数覆盖检查节点的 `target_count`；检查计数控制重复和禁用，下一次运行不继承禁用状态。
- 路线读取 `mirror.node_scores`；卡包读取 `theme_pack.<名称>.weight`。保留旧 Android 扁平配置的读取兼容。
- 任务取消/结束先确认引擎已停止，再释放模型、任务占用和资源版本锁；保留显示、预览和手动输入。明确关闭、下一次启动或其它游戏启动时再释放设备。停止被拒绝时保留任务占用，允许重试。
- 资源下载、版本和更新入口在首页；首次执行也会安装。下载不随首页卡片滚出可见区域而取消。固定提交首次安装无需 GitHub tags API；检查更新才访问 API，失败保留旧资源。
- 任务页仅在明确执行失败或新发现的真实崩溃后显示诊断入口；普通状态短暂提示，日志导出始终可从设置进入。导出包包含边狱任务阶段、当前节点和信息/警告/错误日志。
- 用户配置存 DataStore，和可替换资源目录分开，更新不覆盖队伍/策略。图鉴和图片只读取已安装的 LALC 资源，APK 不再携带图鉴副本；下载前可以编辑任务和队伍，图鉴选择需先下载资源。安装新的资源版本后刷新图鉴与图片。
- 每次启动读取当前资源包的 `config/language` 词表。中文 OCR 通过译名匹配，再返回英文资源标识，让饰品允许/排除、技能替换和事件优先选项使用同一套配置；兼容上游 `RyoShu` / 前端 `Ryoshu` 的拼写差异。
- E.G.O 开关已接入危险拼点分类、头像可用评分和逐张 0% 侵蚀检测。全未选中时重试；每名罪人独立确认选择状态，丢帧不视作成功，长按取消时保证抬起触点。
- 颜色、特征、多尺度、精确匹配分别实现；战斗技能图标复用多尺度匹配。彩色/灰度缓存分开，模板和截图使用相同灰度转换，裁剪越界不扩大到全屏。
- 三个分类模型在连接时试运行并检查输出类别数、有限数值。加载或推理失败明确终止；商店按已购标记过滤商品，保留原槽位并按本轮购买次数修正位移。

## 验证和待验证

Android 标题页允许保留英文按钮，即使游戏内容使用中文。开始登录时单独匹配已下载资源中
两种语言的 `clear_all_caches`，仅用它判断页面，实际点标题页的开始区域；匹配不到时再
识别开始文字或两个相邻的标题页按钮。不会更改游戏内模板语言。连续点击仍不进入游戏、
或持续无法识别页面时有重试上限并报告失败。流水线执行上游的 `pre_delay` / `post_delay`，
避免点击后立刻返回。

使用 2026-09-09 手机截图中的游戏区域做 OpenCV JNI 回归：中文模板不匹配，英文模板
得分 0.899，能定位到开始区域。入口为 `TitleScreenNativeTest.main`，依次传入本机 OpenCV
JNI 库、LALC 资源根目录、1280×720 的标题页截图；Java OpenCV jar 必须和 JNI 库同版本。
这验证的是识别及点击目标，完整登录和游戏任务仍需真机确认。

2026-09-09 的另一张手机主页截图显示导航图标约为桌面模板的 1.4 倍：原模板匹配得分
0.47，无法达到 0.85 阈值。`AndroidHomeNavigation` 仅对三个主页导航锚点在右下区域
进行有限尺度搜索，仍使用下载的 LALC 模板。手机回放中 Drive 得分 0.957、Window
得分 0.877；标签通过独立 OCR 校验所选语言。`HomeNavigationNativeTest.main` 接收
相同的三个参数（最后一个为主页截图），确认英文主页不再进入返回主页分支，中文语言
选择仍拒绝英文标签，空白加载画面不会复用旧识别。回放使用 OpenCV JNI 和 ONNX Runtime
1.19.2 的真实模型；OCR 字符表直接按标准 UTF-8 从模型读取，避免 JNI 对增补字符的截断。

747 的 22:48 日志另有一次语言误报：前一轮主页已确认英文，进入经验任务时又被
`game_language_confirm` 拦截。使用对应截图回放，OCR 将 `Drive` 读为 `Drlre`，
置信度 0.763。语言判断现允许在强 Drive 图标锚点下，用位置独立的两个导航标签
共同确认英文，至少一个必须精确匹配；不降低其它游戏模板的阈值。该截图与此前
主页截图均通过真实 OpenCV/ORT 回放，包含上游 `main_drive_confirm` 子链的实际调度和
点击坐标检查；中文配置仍拒绝这些英文画面。截图回放不能验证点击后的游戏页面变化。

语言错误动作会在转场或 OCR 不清晰时有限重试。只有明确检测到另一种语言才报告
配置不匹配；持续看不清时提示检查游戏画面，不能把“不命中”直接解释成“选错语言”。
任务级失败原因在宿主日志按错误级别显示，并保留到任务结束，不再只剩泛化的完成失败提示。

Android 点击与键盘输入需要按下持续时间，滑动需要分帧移动；不能把 DOWN/UP 或
全部 MOVE 在同一帧内连续发送。输入帮助器统一处理这些时序，并在取消和异常时
释放已尝试注入的触点或按键。虚拟时间测试验证时序与释放；游戏对输入的实际响应
仍需真机复测。

配置保存重载、上游数组转换、技能编码、卡包/路线权重、旧配置迁移、检查节点计数/子链调度、资源原子替换及设备会话生命周期均有 JVM 测试。真实 LALC v5.0.0 源码归档已通过 647 个资源文件的安装和 SHA-256 校验。

747 基线回归：App 843、Arknights 33、engine/api 7、Limbus 268、core/remote 78，合计 1229 项 JVM 测试通过，无失败或跳过。后续安装包的结果随 `out/apk` 中的验证记录保存。此前在 macOS OpenCV 4.9 上运行了 8 项算法 native 测试和 5 项取帧/缓存/裁剪集成测试；Android 编译使用 OpenCV 4.11。三个原始分类模型也通过主机 OpenCV DNN 的输入/输出维度及有限数值检查。主机验证不代表 Android ONNX Runtime 或游戏实机流程已验收。

原生测试入口为 `AdvancedTemplateMatcherNativeTest`、`LimbusRecognizerNativeTest` 的 `main`，参数传本机 OpenCV JNI 动态库绝对路径，运行时 Java jar 必须与该动态库同版本。它们需要已经编译的 engine/limbus 主代码、测试代码、engine/api，以及 Kotlin/协程/OpenCV/ONNX Runtime Java 类；缺 native 库直接失败，不会跳过测试。

当前没有连接 Android 真机：尚未完成页面在手机上的视觉/触控验收，也没有证明登录、OCR、选队、战斗、镜牢全程可用。移动端布局使用 Compose，未直接运行桌面的 Flutter/PyQt 页面。
